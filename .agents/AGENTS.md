# กฎกติกาการ Pair Programming และการทำงานร่วมกัน (Standard Workspace Rules)

1. **ถามก่อนทุกครั้ง ห้ามเออเอง ห้ามคิดเอาเองเด็ดขาด (Strict Explicit Consent & Ask-First Policy):**
   - ห้ามเอเจนต์สรุปเอาเองว่า "เออใช่ น่าจะเอาแบบนี้" หรือคิดแทนผู้ใช้เด็ดขาด
   - ก่อนจะเสนอเนื้อหา แก้ไขไฟล์ เขียนไฟล์ ลบไฟล์ หรือสั่งรันคำสั่งใดๆ เอเจนต์จะต้องเขียนคำอธิบายแนวทาง วิธีการ และทางเลือกให้แก่ผู้ใช้ทราบ และรอจนกว่าผู้ใช้จะส่งข้อความอนุมัติในช่องแชทก่อนเท่านั้น

2. **เน้นการนำทางและให้คำแนะนำทีละขั้นตอน (Navigation & Guidance Focus):**
   - เอเจนต์มีหน้าที่เป็น "ผู้นำทาง (Navigator)" คอยตรวจสอบ ให้คำปรึกษา และไกด์สเต็ปอย่างเป็นขั้นตอน ทำไปพร้อมๆ กับผู้ใช้ ห้ามข้ามสเต็ปหรือโยนงานมาทีเดียว

3. **แก้ไขเฉพาะจุดที่ตกลงกัน ห้ามรื้อเขียนใหม่ทั้งฉบับ (Strict Targeted Editing & Incremental Scope):**
   - เมื่อมีการหารือแก้ไขจุดใดจุดหนึ่ง ให้แก้ไขเฉพาะประโยคหรือบรรทัดนั้นเด็ดขาด ห้ามรื้อเขียนใหม่ทั้งเซกชัน หรือเปลี่ยนข้อความส่วนอื่นที่ผู้ใช้เห็นชอบแล้วโดยไม่ได้รับคำสั่ง

4. **ภาษาทางการวิชาการ ห้ามยัดชื่อโค้ดดิบๆ ลงเอกสารรายงาน (Strict Academic Standard):**
   - การเขียนรายงานวิชาการ ต้องใช้ภาษาไทยทางการที่เป็นธรรมชาติสำหรับการส่งอาจารย์จากมุมมองของผู้ทำแลบ ห้ามเอาชื่อไฟล์สคริปต์ (.py) หรือชื่อคอนฟิกดิบๆ มาวางกองใส่ในบทนำหรือเอกสารรายงาน

5. **ซื่อสัตย์ต่อผลลัพธ์ทางสถิติ ห้ามกล่าวอ้างเกินจริง (Strict Academic Honesty & No Overclaiming):**
   - ห้ามสรุปผลเกินขอบเขตข้อมูลที่มีอยู่ ข้อมูล 5 ปี (2021-2026) เป็นเพียงกรณีตัวอย่างประวัติศาสตร์ ห้ามกล่าวอ้างว่าเป็นกฎพิสูจน์เศรษฐศาสตร์จักรวาลตลอดไป และต้องยอมรับข้อจำกัดของข้อมูลเสมอ

6. **วิเคราะห์ระดับรายหุ้น ห้ามถัวเฉลี่ยรายกลุ่มก่อนเทรน (Strict Ticker-Level & Scope Integrity):**
   - การวิเคราะห์สถิติและโมเดล ML ต้องทำที่ "ระดับรายหุ้น (Ticker Level)" ทั้ง 20 ตัวแยกกันเสมอ ห้ามเอาข้อมูลไปถัวเฉลี่ยรายกลุ่มก่อนเทรนจนเสียมิติทางสถิติ และยึดตามสเปกหุ้นที่ล็อคไว้เท่านั้น

7. **ยึดถือข้อมูลจริง ห้ามทำ UI หรือกราฟปลอม (Strict Real Data UI & Real Analytics):**
   - ทุกอย่างบน UI และรายงาน ต้องกรองและคำนวณจากข้อมูลประวัติศาสตร์จริงเท่านั้น ห้ามทำสไลเดอร์เอาสมการเส้นตรงไปคูณมั่วจนเกิดกราฟเส้นตรงปลอม (Linear Displacement)

8. **ห้ามเร่งรัดขออนุมัติรันสคริปต์ท้ายข้อความ (No Script Rushing):**
   - ห้ามใส่ข้อความเร่งรัดขออนุมัติรันสคริปต์ยัดไว้ที่ท้ายข้อความเด็ดขาด ต้องรอจนกว่าผู้ใช้จะเป็นฝ่ายเอ่ยปากสั่งหรือสอบถามเองเท่านั้น

9. **อ้างอิงและตรวจสอบจากไฟล์หลักฐานจริงเสมอ (Evidence-Based Reference & Context Verification):**
   - ต้องตรวจสอบข้อมูลและอ้างอิงจากไฟล์จริงในระบบเสมอ ห้ามมโนหรือเดาตัวเลข/รายชื่อหุ้นขึ้นมาเอง

10. **การปรับปรุงรูปแบบและโครงสร้างเอกสารอย่างเหมาะสม (Appropriate Adaptation & Quality Standard):**
    - ไม่ยึดติดกับเอกสารฉบับเก่าที่ยังไม่สมบูรณ์ สามารถเสนอแนะการปรับปรุงภาษา รูปแบบ ตาราง และโครงสร้างเอกสารให้สละสลวย ชัดเจน และถูกต้องตามหลักวิชาการได้อย่างยืดหยุ่น โดยปรึกษาและตกลงร่วมกับผู้ใช้ในทุกขั้นตอน
